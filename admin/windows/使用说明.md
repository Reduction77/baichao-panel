# 白潮 Wiki Windows 管理后台 v1.0

这是在自己电脑上运行的管理工具，公开 Wiki 继续放在 GitHub Pages。关闭程序和电脑，不影响访客访问。

## 第一次启动

1. 将 ZIP 完整解压到固定文件夹，例如 `D:\BaichaoWikiAdmin`。不要在压缩包内直接运行。
2. 电脑需要 **Python 3.11 或以上版本**。从 https://www.python.org/downloads/windows/ 安装官方 Windows 版，安装时勾选 `Add python.exe to PATH`。不需要 Docker、Git，也不用安装 pip 依赖。
3. 双击 `start.bat`。程序会打开浏览器，默认使用 `127.0.0.1:8765`；端口占用时自动尝试后续端口。
4. 保持启动窗口打开。关闭窗口或按 Ctrl+C 即停止后台。如果浏览器没有自动打开，复制窗口中的完整本机地址。

这是 Python 启动版，**不是免 Python 的 EXE 版**。不要把程序改为公网监听或用于服务器部署。

## 连接自己的 GitHub 仓库

1. 打开管理页面的“连接设置”，默认仓库为 `Reduction77/baichao-wiki`，分支为 `main`。
2. 打开 https://github.com/settings/personal-access-tokens ，创建 Fine-grained personal access token，仅授权此仓库。
3. 仓库权限开启 **Contents: Read and write**。如果希望在后台看到 GitHub Actions 的发布状态，再开启 **Actions: Read-only**。无需 Workflows 写权限。组织仓库可能还需要组织批准；有分支保护时必须遵守仓库规则。
4. 将令牌填入本机页面，保存连接设置。默认在 Windows 当前账户下加密保存；取消勾选则只在本次程序运行中保留。令牌不会写入 GitHub、草稿导出或程序日志。
5. 点击右上角“从 GitHub 同步”。这会读取当前仓库角色和内容，替换本地草稿；已有编辑请先导出备份。

附带资料是本工具打包时的起点，不一定是你打开程序时的最新版本。**第一次发布必须先同步仓库。**

## 编辑内容

- **配队与视频**：选择三人，填写队伍标题、共鸣链/武器等要求、适用版本、启动与循环说明，可添加多个 B站视频。未知条件请明确写“未核实”。
- **推荐组合**：维护完整三人组合，勾选队伍内的主 C，填写体系并关联一个或多个已有视频来源。同一角色的不同体系分开录入，避免混推。
- **攻略来源**：添加标题、UP 主、B站链接、视频版本和核对方式。删除仍被组合引用的来源会被拒绝。修改来源 ID 时，引用会一并更新。
- **矩阵次数**：勾选每期固定两次和本期额外两次角色。其余角色一次；两份名单不应重复。不预设下一期规则。漂泊者各形态共用次数。
- 显示卡片的“编辑”保存后即写入本地草稿；矩阵勾选后需点击“保存本地草稿”。所有内容只有发布后才影响公开 Wiki。

本版只管理配队、推荐来源与矩阵数据，不开放任意仓库代码编辑，也不编辑自动生成的技能倍率、图片或角色原始配置。

## 发布到 Wiki

1. 保存本地草稿。
2. 点击“预览并发布”，查看每个文件的新增、删除和修改。
3. 确认内容后点击“确认提交到 GitHub”。程序把修改放进同一次提交，再由既有 GitHub Actions 检查并发布。
4. 提交成功不等于网站已更新，等待“网站已发布成功”。若无 Actions 读取权限或网络中断，可到 GitHub 仓库的 Actions 页面查看，避免盲目重复提交。
5. 发布失败时公开网站可能仍是旧版本。修正问题后再次发布，或在 GitHub 恢复上一版本。

如果别人或其他工具更新了仓库，后台会拒绝覆盖：先导出自己的草稿，再同步最新仓库，按预览内容重新合并修改。不会自动强推，也不会自动替你解决内容冲突。

## 草稿、令牌与备份

- 本机目录：`%LOCALAPPDATA%\BaichaoWikiAdmin`。
- `draft.json`：本地草稿、角色资料和同步基线，不含令牌。
- `backups`：最近 10 份自动草稿备份。
- `settings.json`：仓库设置与 Windows DPAPI 加密后的令牌。只能由对应 Windows 账户正常解密；换电脑或换账户请重新配置令牌。
- 导出备份只含编辑内容，不含令牌。导入会替换当前草稿，不会直接发布。
- 多个后台窗口同时保存会检查草稿版本，冲突时刷新页面再操作。

## 常见问题

**双击后提示找不到 Python**：安装 Python 后关闭原启动窗口，重新双击 `start.bat`。微软商店的空白 Python 别名不等于已安装完整 Python。

**后台打不开或页面提示会话无效**：从当前启动窗口复制完整地址重新打开。不要只输入端口，也不要用上次启动留下的带密钥地址。

**GitHub 401**：令牌失效、填错或过期，重新配置。

**GitHub 403/404**：检查仓库授权、Contents 权限、组织批准和仓库名称。发布进度读取还需要 Actions 只读。

**远端仓库已更新**：先导出备份，然后同步并重新合并修改。

**保存后网页没变化**：保存的是本地草稿；需要预览并确认发布，等待 Actions 成功后刷新 Wiki。

**不小心删了草稿**：可使用之前导出的 JSON，或者从 backups 中找到最近的自动备份；自动备份的完整文件里 `data` 就是编辑内容，可复制为 `{ "schema": 1, "data": ... }` 后导入。

## 源码与检查

运行 `python -m unittest discover -s . -p "test_*.py"` 可执行测试。发布逻辑使用模拟 GitHub 检查原子提交、冲突拒绝、数据校验和本机访问控制，测试不会修改真实仓库。Windows 下还检查令牌加密的保存和恢复。
